# Team_poker — исправление переноса задачи со статусом «Не начата»

## Реальная причина

Предыдущая версия `firestore.rules` уже могла быть опубликована и при этом
перенос всё равно завершался ошибкой `permission-denied`.

Функция переноса читает всю коллекцию:

```text
issues/{issueId}/votes
```

Старое правило разрешало читать:

- собственный голос;
- голоса прошлых раундов;
- все голоса после `revealed` или `estimated`.

Для задачи со статусом `pending` администратор или тимлид не мог выполнить
запрос ко всей коллекции `votes`. Firestore проверяет возможность запроса
по правилам, а не по фактическому наличию документов, поэтому отклонялось
даже чтение пустой коллекции.

## Исправление

Администратору и тимлиду разрешено читать всю коллекцию голосов, если:

```text
status != voting
```

или если создаётся проверяемая копия:

```text
moveState == copying
```

Во время активного голосования (`status == voting`) чужие голоса остаются
скрытыми.

## Что опубликовать

Обязательно:

```text
firestore.rules
```

Рекомендуется:

```text
app.js
```

В `app.js` уточнено диагностическое сообщение с указанием этапа переноса.

## Firebase CLI

```bash
firebase deploy --only firestore:rules --project team-poker-6c06f
```

После обновления сайта:

```text
Cmd + Shift + R
```
